아날로그 TV 노이즈가 실제로 왜, 어떻게 생기는지 정리하고, 이를 WebGPU(WGSL) 프래그먼트 셰이더로 옮긴 방법을 적었다. 옆 화면의 파라미터를 움직이면 각 요소가 화면에 어떻게 드러나는지 바로 볼 수 있다.

1. 진짜 TV 노이즈의 정체

방송 신호가 없는 채널에 아날로그 TV를 맞추면, 튜너와 증폭기는 신호를 못 찾고 최대 이득(gain)으로 올라간다. 그러면 안테나와 회로가 받아들이는 온갖 잡음이 그대로 화면 밝기로 그려진다. 이것이 "snow(눈)"라고 부르는 지지직 화면이다.

  • 대부분은 수신기 자체의 열잡음(thermal noise)이다. 특히 안테나가 연결된 첫 번째 증폭 트랜지스터에서 많이 나온다.
  • 그 밖에 사람이 만든 전파, 태양 같은 천체 전파원도 섞인다.
  • 약 1% 정도는 우주 배경 복사(CMB), 즉 빅뱅의 잔광이라는 이야기가 유명하다. 1964년 펜지어스와 윌슨이 안테나에서 지워지지 않는 잡음을 쫓다가 CMB를 발견한 일화와 이어진다. (대중 매체 기준 근사치)

시각적 특징 (구현할 때 참고할 사실들)

특징이유
거의 흑백이다컬러 TV는 컬러 버스트(color burst) 신호가 없으면 color killer 회로가 색 신호 처리를 꺼 버린다. 그래서 대부분 회색 알갱이로 보이고, 기종에 따라 아주 약한 색 얼룩만 남는다.
프레임마다 완전히 새로 바뀐다열잡음은 시간적으로 상관이 없다. 직전 프레임과 전혀 관계없는 패턴이 나온다.
알갱이가 가로로 조금 길다아날로그 영상은 주사선을 따라 가로 방향으로 연속 신호인데, 대역폭이 제한되어 가로 방향으로 약간 번진다. 세로는 주사선 단위로 끊긴다.
밝기 분포가 가우시안에 가깝다열잡음은 정규분포를 따른다. 균일 분포 난수를 그대로 쓰면 "너무 디지털"해 보이니, 여러 개를 평균내 종 모양 분포를 흉내 낸다.
주사선이 보인다NTSC는 525줄(보이는 건 약 480줄), 약 60필드/초 인터레이스다. 줄 사이의 어두운 틈이 질감을 만든다.
가끔 흐르는 띠나 가로 흔들림이 있다수직/수평 동기 신호가 없어서 화면이 위아래로 굴러가거나(roll), 줄마다 가로 위치가 흔들린다.
"쉬이이" 하는 소리오디오도 같은 원리로 화이트 노이즈가 된다. 화면과 같이 내면 체감이 크게 좋아진다.

3. GPU에서 난수 만들기

셰이더에는 rand()가 없고 이전 프레임 상태도 없으니, 입력 좌표 → 난수인 해시 함수를 쓴다. 입력은 (셀 x, 셀 y, 프레임 번호)다.

흔한 함정: fract(sin(dot(p, …)) * 43758.5453)

인터넷 셰이더에 가장 많이 보이는 한 줄 난수지만, sin의 정밀도가 GPU/드라이버마다 달라서 기기에 따라 줄무늬 패턴이 생기거나 큰 입력값에서 품질이 무너진다. 시간을 입력에 넣으면 시간이 커질수록 더 나빠진다. Dave Hoskins의 "Hash without Sine"이 이 문제를 피하려고 나온 대안이다.

추천: 정수 해시 PCG (pcg3d)

Jarzynski & Olano의 논문 Hash Functions for GPU Rendering(JCGT 2020)은 100개가 넘는 해시를 품질(TestU01)과 속도로 비교했다. 품질-속도 균형이 가장 좋은 쪽으로 PCG를 꼽았고, 다차원 입력/출력용으로 pcg3d를 제안했다. WGSL은 u32 곱셈과 덧셈이 오버플로 시 래핑되므로 그대로 옮길 수 있다.

fn pcg3d(v_in: vec3u) -> vec3u {
var v = v_in * 1664525u + 1013904223u;
v.x += v.y * v.z; v.y += v.z * v.x; v.z += v.x * v.y;
v ^= v >> vec3u(16u);
v.x += v.y * v.z; v.y += v.z * v.x; v.z += v.x * v.y;
return v;
}
// 0..1 실수로: vec3f(pcg3d(...)) / 4294967295.0

입력이 (x, y, frame) 세 개라 pcg3d가 딱 맞는다. 출력도 3개라서 그대로 평균내 가우시안 근사에 쓰거나, RGB 색 얼룩으로 쓸 수 있다.

좌표를 u32로 바꾸기 전에 음수가 되지 않게 오프셋을 더한다. WGSL에서 음수 f32 → u32 변환은 0으로 고정(clamp)되어 같은 값이 반복된다.

4. 갤러리 예제 구조로 옮기기

이 저장소의 예제는 WorkModule(meta, init, frame(time), dispose, 선택적 resize)을 export 한다. 지지직 효과는 정점 버퍼 없이 전체 화면 삼각형 하나 + 유니폼 버퍼 하나로 충분하다.

  1. src/works/tv-static/index.ts와 thumbnail.svg를 만들고 src/works/index.ts에 등록한다.
  2. init: 셰이더 모듈, 렌더 파이프라인(format은 넘겨받은 gpu.format), 48바이트 유니폼 버퍼, 바인드 그룹을 만든다. 캔버스 크기는 canvas.width/height에서 읽는다.
  3. frame(time): 해상도, 시간, 파라미터를 queue.writeBuffer로 올리고 draw(3)을 한 번 호출한다.
  4. resize: 해상도는 매 프레임 유니폼으로 보내므로 따로 다시 만들 리소스가 없다. 캔버스 참조만 들고 있으면 된다.
// src/works/tv-static/index.ts (뼈대)
import type { GpuContext, WorkMeta } from '../types'
import thumbnail from './thumbnail.svg'
import shaderCode from './static.wgsl?raw'   // Vite의 ?raw 로 문자열 import

export const meta: WorkMeta = { title: 'TV Static', description: '신호 없는 아날로그 TV 화면', thumbnail }

let device: GPUDevice | null = null
let context: GPUCanvasContext | null = null
let canvas: HTMLCanvasElement | null = null
let pipeline: GPURenderPipeline
let uniformBuffer: GPUBuffer
let bindGroup: GPUBindGroup
const uniforms = new Float32Array(12)

export function init(c: HTMLCanvasElement, d: GPUDevice, gpu: GpuContext) {
canvas = c; device = d; context = gpu.context
const module = d.createShaderModule({ code: shaderCode })
pipeline = d.createRenderPipeline({
  layout: 'auto',
  vertex: { module, entryPoint: 'vs' },
  fragment: { module, entryPoint: 'fs', targets: [{ format: gpu.format }] },
})
uniformBuffer = d.createBuffer({ size: 48, usage: GPUBufferUsage.UNIFORM | GPUBufferUsage.COPY_DST })
bindGroup = d.createBindGroup({
  layout: pipeline.getBindGroupLayout(0),
  entries: [{ binding: 0, resource: { buffer: uniformBuffer } }],
})
}

export function frame(time: number) {
if (!device || !context || !canvas) return
uniforms.set([canvas.width, canvas.height, time, /* grain */ 1.5, /* scan */ 0.35,
              /* roll */ 0.5, /* chroma */ 0.1, /* fps */ 30, devicePixelRatio, /* jitter */ 0.2])
device.queue.writeBuffer(uniformBuffer, 0, uniforms)
const encoder = device.createCommandEncoder()
const pass = encoder.beginRenderPass({ colorAttachments: [{
  view: context.getCurrentTexture().createView(), loadOp: 'clear', storeOp: 'store',
  clearValue: { r: 0, g: 0, b: 0, a: 1 } }] })
pass.setPipeline(pipeline); pass.setBindGroup(0, bindGroup); pass.draw(3); pass.end()
device.queue.submit([encoder.finish()])
}

export function dispose() { device = null; context = null; canvas = null }

5. 주의할 점

  • 알갱이 크기는 CSS 픽셀 기준으로. 러너가 캔버스를 CSS 크기 × devicePixelRatio로 맞추므로, 셀 크기에 dpr을 곱하지 않으면 레티나/4K에서 노이즈가 너무 잘아져 회색 면처럼 보인다.
  • 프레임 레이트를 고정한다. 노이즈를 rAF마다 갱신하면 고주사율 모니터에서 너무 빨라 오히려 평평한 회색으로 보인다. 30fps 근처가 실제 TV 느낌에 가깝다.
  • 밝기 기준. 기본 캔버스 포맷(bgra8unorm)은 셰이더 출력값이 그대로 표시되므로 별도 감마 처리 없이 0~1을 "보이는 밝기"로 다루면 된다. -srgb 포맷을 쓰면 같은 값이 더 밝게 보이니 대비를 다시 맞춰야 한다.
  • 해시 입력의 정밀도. fragCoord를 float 그대로 해시하면 브라우저/GPU에 따라 정지 화면에서도 패턴이 깜빡였다는 보고가 있다. 반드시 floor로 셀 정수 좌표를 만든 뒤 u32로 바꿔 해시한다.
  • 광과민성. 화면 전체가 빠르게 번쩍이는 효과다. 롤링 띠의 밝기 변화를 과하게 주지 말고, 필요하면 블로그 임베드에서는 강도를 낮춘다.
  • 시간 값. 러너의 time은 초 단위 누적값이다. 프레임 번호 u32는 30fps로 4년 넘게 돌아야 넘치니 걱정할 필요는 없다.

6. 확장 아이디어

  • 채널 전환: 클릭하면 노이즈가 걷히고 약한 신호(테스트 패턴, 희미한 이미지)가 비쳐 보이도록 signal 값을 섞는다. 약한 신호 + 노이즈가 "잡히다 말다 하는" 느낌을 준다.
  • 소리: Web Audio로 무작위 샘플을 채운 AudioBuffer를 반복 재생하고, 밴드패스 필터로 TV 스피커 느낌을 낸다. 브라우저 자동재생 정책 때문에 사용자 클릭 이후에만 시작할 수 있다.
  • CRT 질감: 배럴 왜곡, RGB 섀도 마스크/어퍼처 그릴, 블룸. Timothy Lottes의 CRT 셰이더가 표준적인 참고 자료다.
  • 인광 잔상: 렌더 타겟 텍스처 2장을 번갈아 쓰며 mix(prev, cur, 0.6). 노이즈가 조금 부드러워지고 아날로그 느낌이 강해진다.
  • VHS 계열: 테이프 주름, 트래킹 노이즈, 색 번짐(chroma bleed)까지 가면 VCR 왜곡 셰이더들(FMS_Cat, Ryk)을 참고한다.
